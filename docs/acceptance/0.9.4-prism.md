# ChiseTweaks 0.9.4 Prism Acceptance

この手順は **実機でしか確認できない描画・入力・接続・FPS観点**を、毎回同じ順序で確認するための受入プロトコルです。CIの成功だけではこの文書の項目をPASS扱いにしません。

## 前提

- Minecraft `26.1.2`
- Fabric Loader `0.19.3` 以上
- Fabric API `0.155.2+26.1.2` 以上
- Java `25`
- ChiseTweaks `0.9.4+mc26.1.2` candidate JAR
- 同じPrism instance、同じ描画設定、同じResource Packs、同じshader条件で比較する
- 実施前に必要なログとperformance evidenceを退避する

## A. 起動・Mixin

1. クリーン起動し、タイトル画面まで到達する。
2. `latest.log` に `client-startup` diagnostic eventが存在することを確認する。
3. `MixinTransformerError` / `MixinApplyError` / `InvalidMixinException` / `Mixin apply failed` がないことを確認する。
4. 起動直後にChiseTweaksのcomponent quarantine / resource reload failureがないことを確認する。

ログ監査:

```bash
python scripts/prism_acceptance_audit.py <instance-root>/logs/latest.log
```

## B. 11 runtime features 同時利用

11個のruntime featureをすべてONにし、それぞれが他機能を自動OFFにしないことを確認する。

重点組み合わせ:

- Fine Line Highlight + Hidden Block Highlight + Nether Highlight
- Visual Filter Blocks + Visual Filter Entities
- Low Fire
- Lava Analyzer + Ancient Debris Analyzer
- Bright Chest + Bright Concrete

## C. Visibility Resource Packs

1. Bright ChestをON/OFF/ONする。
2. reload終了を待たずBright ConcreteもOFF/ONする。
3. 連打後に描画が最後の要求状態へ収束することを確認する。
4. ChestとWhite Concreteが独立して切り替わることを確認する。
5. Prism Launcher / `latest.log` に `resource-reload-failure` / `resource-reload-terminal-failure` が出ないことを確認する。

## D. Analyzer

### Lava Analyzer

- Lava Analyzerを有効化する。
- 溶岩源だけが対象となり、流動中の溶岩を誤って源泉として扱わないことを確認する。
- 読み込み境界を移動しても強制的なchunk loadによる停止感がないことを確認する。

### Ancient Debris Analyzer

- Ancient Debris Analyzerを有効化する。
- 既存の古代の残骸が表示されることを確認する。
- 読み込み済み範囲内で古代の残骸を追加し、再検証後に表示されることを確認する。
- 対象を削除し、再検証後に表示から消えることを確認する。
- 最大range / marker設定でも操作不能な長時間停止が発生しないことを確認する。

## E. Session / dimension

1. Overworldへjoinする。
2. Netherへ移動する。
3. 必要に応じEndも確認する。
4. disconnectする。
5. 同一または別worldへreconnectする。
6. 前sessionのAnalyzer markerやquarantine状態が不正に残らないことを確認する。

join/disconnectまで含めて監査する場合:

```bash
python scripts/prism_acceptance_audit.py <instance-root>/logs/latest.log --require-join --require-disconnect
```

`Connection reset` はtransport disconnectとして集計します。それ単体をChiseTweaks crashとは判定しません。

## F. 0.9.1 migration

0.9.1相当の旧Visibility pack選択を持つ複製instanceで確認する。

- 旧単一packが選択済み → Chest / White Concreteの2packへ移行
- 旧単一packが無効 → 意図しない再有効化をしない
- 他Resource Packの選択順を壊さない
- すでにsplit packを個別設定済みの場合、その状態を優先する

本番instanceをmigration試験用に直接書き換えない。

## G. Prism Diagnostics

設定画面にはdiagnostic utilityを置かず、Prism Launcherのコンソール / `logs/latest.log` を診断の正とする。

- `Chise diagnostics event=client-startup` が起動時に出力される
- join / disconnect時に対応diagnostic eventが出力される
- resource reload / recovery failure時に対応eventと`reloadState`を確認できる
- component quarantine時に`componentId` / `failure`を確認できる
- diagnostic行にserver address、ユーザー名、絶対local pathを追加収集しない
- `prism_acceptance_audit.py` がtransport disconnectとChiseTweaks failureを分離できる

## 合格条件

- 上記A〜GがすべてPASS
- ChiseTweaks起因のMixin error / component quarantine / reload failureなし
- 重大な視覚回帰なし
- Performance evidenceの5scenario比較が別手順でPASS

実機確認が終わるまでは **0.9.4 manual acceptance = NOT EXECUTED** と扱います。
